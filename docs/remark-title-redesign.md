# 备注与分类系统重设计方案

> 状态：预留设计，待下一版本实施。当前版本保留现有 `remark` 字段逻辑，本文档描述目标态。

---

## 一、核心原则

**分类（title）和备注（note）是两个独立字段，职责不重叠。**

| | 分类标题 `title` | 备注 `note` |
|---|---|---|
| 定位 | 卡片归属哪个项目/分组 | 对这条卡片的文字说明 |
| 示例 | "a项目"、"b项目"、"待办" | "这个接口还需要加参数校验" |
| 长度限制 | ≤ 30 字 | ≤ 500 字 |
| 显示位置 | header 彩色 chip（替代类型名） | 卡片右下角，小字浅色 |
| 弹窗展示 | 不需要（header 已显示） | 弹窗底部新增备注展示栏 |
| 筛选方式 | dock 分类 chip，点击筛选 | 顶栏搜索框"备注"模式，独立筛选 |
| 颜色 | 按内容 hash 自动生成 | 无颜色，纯文字 |
| 自动补全 | 有（历史标题值下拉） | 无 |

**字段命名**：现有 `remark` 保留为备注（不改名），新增 `title` 字段作为分类标题。

---

## 二、分类标题（title）

### 2.1 编辑入口

- 卡片底部 meta 栏常驻 `+ 标题` 按钮（无标题时）/ 彩色 chip（有标题时）
- 点击打开编辑弹窗，弹窗内输入框带自动补全下拉
- 自动补全列表从所有卡片的 `title` 聚合，显示：颜色点 + 标题文字 + 使用条数
- 键盘 ↑↓ 选择，Enter 确认，Esc 关闭
- 单卡编辑，不做批量归类

### 2.2 显示

- 有标题：header 里彩色 chip 替代类型名，chip 颜色按标题内容 hash 生成
- 无标题：header 显示原类型名（文本/代码/链接/图片/文件）
- 点击 chip = 触发分类筛选

### 2.3 筛选（dock 分类 chip）

- dock 底部在类型 chip 之后动态追加分类 chip
- 从所有卡片 `title` 聚合，按使用条数降序排列
- chip 带颜色点（和卡片 header 上的 chip 同色）
- 点击 chip = 只看该标题的卡片，再点一次取消
- 分类筛选和类型筛选是 AND 关系，可叠加
- 分类筛选和备注筛选**互斥**：进入备注筛选模式时自动清除分类筛选

### 2.4 搜索覆盖

- 顶栏搜索的"全部"模式覆盖 `title` 字段
- 搜索"a项目"能找到标题为"a项目"的卡片

## 三、备注（note）

### 3.1 编辑入口（两处）

**入口 A：卡片右下角**
- 有备注：显示备注前 15 字 + 省略号，灰色小字，点击直接进入编辑
- 无备注：显示 `+ 备注` 淡显按钮，点击直接进入编辑
- 编辑方式：行内展开输入框，或弹出备注弹窗（复用现有弹窗）

**入口 B：卡片详情弹窗底部**
- text-viewer / image-viewer / file-viewer 底部新增备注展示栏
- 有备注时显示备注全文 + "编辑"按钮
- 无备注时显示"+ 添加备注"链接
- 点击编辑/添加直接打开备注弹窗

### 3.2 显示

- 卡片右下角：备注预览（前 15 字 + 省略号），灰色 `var(--text-muted)` 小字
- 卡片详情弹窗底部：备注全文 + 编辑按钮
- header 不显示备注（备注和标题完全分离）

### 3.3 筛选（顶栏搜索框扩展）

**独立模块，和分类筛选互斥。**

顶栏搜索框新增模式切换：

```
[全部 | 备注] 搜索...
──────────────────
📝 卡片A
  "这里是备注内容"

📝 卡片B  
  "另一段备注..."
```

- 搜索框左侧两个 tab：`全部`（默认，搜内容和标题）、`备注`（只搜 note 字段）
- 切到"备注"模式时：
  - 清除当前分类筛选（`currentCategoryFilter = null`）
  - 搜索结果只包含有备注的卡片
  - 结果卡片高亮显示备注文字（匹配关键词标黄）
  - 结果列表按备注内容相关性排序
- 切回"全部"模式时恢复正常搜索行为
- 两种模式切换不清空搜索关键词，只改变搜索范围

### 3.4 搜索框 UI

```
┌──────────────────────────────┐
│ [全部] [备注]  🔍 搜索...     │
└──────────────────────────────┘
```

- 两个 tab 用小号 pill 样式，选中态用 accent 色
- 默认"全部"，用户点击"备注"切换
- 切换时不弹窗、不跳页，即时改变搜索范围
- 移动端同样适用，tab 缩小为图标

## 四、卡片详情弹窗底部备注栏

```
┌─────────────────────────────┐
│  [类型图标] 标题    [复制]  │  ← 现有 header
├─────────────────────────────┤
│                             │
│       卡片内容区             │
│                             │
├─────────────────────────────┤
│  📝 备注                     │  ← 新增
│  这里是备注文字内容          │
│  [编辑]                      │
└─────────────────────────────┘
```

- 有备注：显示备注全文 + 编辑按钮
- 无备注：显示 `+ 添加备注` 链接
- 敏感卡片解锁后也显示备注
- 隐私卡片解锁后也显示备注
- 备注区域不随内容区滚动，固定在弹窗底部

## 五、数据模型

### 新增字段

```js
// message 结构
{
  id: "...",
  type: "text",
  content: "...",
  remark: "...",    // 现有字段，保留为备注（note），不改名
  title: "a项目",   // 新增字段，分类标题
  favorite: false,
  timestamp: 1234567890
}
```

### 服务端接口

| 方法 | 路径 | 说明 |
|------|------|------|
| `PATCH` | `/:id/remark` | 现有，更新备注（note） |
| `PATCH` | `/:id/title` | 新增，更新分类标题 |
| `GET` | `/search?q=...&scope=note` | 现有搜索扩展，`scope=note` 时只搜 remark 字段 |

### 搜索范围

- `scope=all`（默认）：搜 content + remark + title
- `scope=note`：只搜 remark 字段，结果只含有备注的卡片

### 现有数据迁移

- 现有 `remark` 值保持不变，继续作为备注
- `title` 字段初始为空，用户手动设置
- 不做自动迁移（现有 remark 值大多像自由文本备注，不一定是分类名）

## 六、`updateSingleMessageRemark` 简化

当前保存备注后需要手动同步 5 处 DOM，容易不一致。改为：

**备注保存后**：对单张卡片做局部重渲——只重建 `metaFooterEl`（底部 meta 栏含备注预览）和弹窗底部备注栏，不触碰 header 和 content。

**标题保存后**：对单张卡片做局部重渲——只重建 `labelsEl`（header 里的 chip），不触碰 content 和 meta。

这样每个字段变更只影响自己的显示区域，不会交叉污染。

---

## 七、互斥逻辑

```
分类筛选（dock chip）  ←→  备注筛选（搜索框备注模式）
         互斥：进入任一方时清除另一方
```

- 点击 dock 分类 chip → 如果当前在备注搜索模式，切回全部模式 + 清除搜索词 + 应用分类筛选
- 搜索框切到"备注"模式 → 清除 `currentCategoryFilter` + 重新渲染 dock chip（取消高亮）
- 类型筛选（文本/代码/图片等）不受影响，可以和两者都叠加

## 八、实施顺序

1. **服务端**：message 结构加 `title` 字段；新增 `PATCH /:id/title` 路由；搜索接口加 `scope` 参数
2. **前端数据**：`createMessageElement` 里分两步渲染 title（header chip）和 remark（右下角预览）
3. **标题编辑**：复用现有备注弹窗，改为标题编辑弹窗；加自动补全
4. **备注编辑**：卡片右下角入口 + 弹窗底部入口，点击直接编辑
5. **dock 分类 chip**：从 `title` 聚合，和现有逻辑一致
6. **搜索框扩展**：加 `全部 | 备注` tab 切换，备注模式只搜 remark
7. **互斥逻辑**：分类筛选和备注筛选互斥
8. **清理**：删除 `paste-card-title` 死代码、`message-remark-box` sr-only 节点
