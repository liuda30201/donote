# 用户自选登录验证

Accounts 模式下，普通用户在“账户与设备安全”中选择仅密码、密码加邮箱验证码或密码加身份验证器。默认未配置二次验证的普通用户使用仅密码；已有启用的 TOTP 保留为 TOTP。管理员和 strict 策略账号仍必须使用 TOTP，不能通过偏好设置降低要求。

邮箱是密码之后的第二步验证，不是免密码登录。邮箱必须先完成收码验证才能启用。修改方式、邮箱或关闭二次验证，需要当前密码和当前启用的验证方式；修改后旧会话全部失效，重新登录。切换到仅密码不会删除已绑定的邮箱或认证器，方便以后重新启用。

## 自主注册

Accounts 模式配置有效 SMTP 后，登录页开放“创建账户”。填写用户名、密码、显示名称和邮箱，收到邮件后输入六位验证码完成注册，再使用用户名和密码登录。用户名为 3–64 位小写字母、数字、点、下划线或短横线，首位必须是字母或数字；密码至少 12 个字符，UTF-8 编码最多 1024 字节。注册仅创建普通用户，不授予管理员权限。

- `POST /api/auth/register/start`：提交 `username/password/email` 和可选 `displayName`，返回挑战令牌，不返回验证码。
- `POST /api/auth/register/confirm`：提交 `challenge/code`，验证邮箱并在同一事务中创建账号、已验证邮箱和仅密码登录偏好；不自动发放登录 Cookie。
- 两个接口都要求 JSON 与允许的 Origin，不需要未登录用户持有会话 CSRF 令牌。
- 独立注册挑战有效期 5 分钟，最多 5 次错误（含格式错误），单次使用；同用户名或邮箱至少间隔 60 秒，每邮箱每小时最多 5 次，每来源每小时最多 10 次，另有 IP 限速和最多两个并发注册任务。
- 为避免查询账号是否存在，重复用户名或邮箱也返回通用挑战及确认结果，但不会覆盖已有账号、密码或邮箱。无法登录时可更换用户名或邮箱重新注册。
- 未配置 SMTP 时隐藏注册入口，接口拒绝注册；传统 legacy 模式不开放注册。
- 新账号默认仅密码登录。登录后在“账户与设备安全”选择邮箱或 TOTP；这两种方式均是密码后的第二因素，管理员及 strict 策略不允许降级。

## 发信配置

使用 `docker-compose.accounts.yml`，在部署 `.env` 中配置：

```dotenv
SMTP_HOST=smtp.example.com
SMTP_PORT=587
SMTP_SECURE=false
SMTP_USER=no-reply@example.com
SMTP_PASSWORD=替换为发信服务授权密码
SMTP_FROM="DoNote <no-reply@example.com>"
```

587 使用强制 STARTTLS；465 通常配置 `SMTP_SECURE=true`。证书校验始终开启。配置后重建/重启应用容器，发件域名的 SPF、DKIM 和 DMARC 按邮件服务商要求设置。不可将 SMTP 密码提交至版本库。直接运行 Node 时需要把这些变量注入进程，应用不会自动读取项目根目录 `.env`。

未配置或配置不完整时，应用继续支持密码和 TOTP；邮箱方式不可用，已有邮箱用户登录会收到发信不可用提示，不能绕过验证码进入。

## 验证规则

- 六位随机数字，有效期 5 分钟，单次使用，最多 5 次错误。
- 每账号发送间隔至少 60 秒、每小时最多 10 次；另有来源与密码验证限速。
- 验证码使用服务器密钥 HMAC 后存储，不写入日志或 API 响应。
- 挑战绑定用户、安全版本、用途、当前会话及操作，不能将登录码用于修改安全设置。
- SQLite migration 2 提供邮箱验证，migration 3 提供独立注册挑战；保留 migration 1、2 原始校验值，运行时和离线账户工具统一应用三次迁移。注册挑战超过一小时在下次发码时清理。
- SMTP 只使用经过证书校验的 TLS 连接，发信错误返回通用错误，不暴露服务端诊断与密码。

测试使用注入的邮件发送器捕获验证码，无需真实发信。正式收件箱投递仍需实际配置 SMTP 后验收。
